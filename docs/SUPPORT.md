## Information to Provide

When reporting a normal technical problem, provide enough technical information to reproduce the problem without exposing secrets or unrelated sensitive information.

Useful information may include:

- LogViewer version
- Core or Pro distribution
- Operating system
- Python version
- Installation method
- Exact command or menu action that produced the problem
- Relevant error message
- Relevant traceback
- Whether the problem is reproducible
- Steps already attempted

Do not send passwords, private keys, customer credentials, API tokens, license issuer credentials, or unrelated sensitive information.

## Security Issues

Security issues should be reported responsibly.

When reporting a security issue, provide enough information for investigation while avoiding unnecessary disclosure of sensitive information.

Include:

- A concise description of the security issue
- Affected LogViewer version
- Reproduction steps where appropriate
- Relevant technical evidence
- Expected behavior
- Observed behavior
- Potential security impact

Do not publicly disclose private exploit details or sensitive information before the issue has been reviewed.

## Private Signing Keys

Private signing keys are issuer-side security material.

Customers must never request, distribute, publish, or include private signing keys in customer support submissions, installation packages, release archives, or public repositories.

The customer-facing license is the signed license artifact. The private signing keys used to issue licenses remain protected issuer-side material.

## License Support

For license activation problems, include:

- LogViewer version
- Core or Pro distribution
- License status output
- License ID, when available
- Relevant verification error
- Whether the license is expired
- Whether the problem occurs immediately after activation

Do not send the private signing keys.
